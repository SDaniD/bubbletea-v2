# BubbleTea 2.0

**BubbleTea 2.0** is an interactive visualization tool designed to showcase the results of layered architecture recovery using the [Deductive SAR](https://doi.org/10.1145/3639476.3639776) technique.

This project builds upon the [original BubbleTea version](https://github.com/rsatrioadi/bubbletea), which was demonstrated at [VISSOFT '24](https://www.linkedin.com/company/ieee-vissoft).

## Getting Started

You can access BubbleTea 2.0 [live](https://satrio.rukmono.id/bubbletea-v2/) ([alternative link](http://rsatrioadi.github.io/bubbletea-v2/)).

### How to Use
1. Click the **Upload** button in the top-left corner of the interface.  
2. Select and upload a JSON file generated by [Arcana](https://github.com/rsatrioadi/arcana) using the `llm` command.  
3. Explore the visualization to understand your software's layered architecture.

## BEP Architecture Review Pipeline

This repository also contains the package-level architectural review extension
used in the bachelor project. The extension enriches a BubbleTea JSON file with:

- package layer-consistency classifications;
- Architecture Review Priority Score (ARPS) metadata;
- LLM-generated architecture explanations;
- maintainability and evolution review text;
- class-level review hints;
- dependency evidence used by the UI analytics panels.

The pipeline should be run after a BubbleTea-compatible JSON file has already
been generated and after a package classification CSV is available.

### Input Files

The default project presets expect the following workspace-level folders:

```text
outputs/
data/csv/
```

Important inputs are:

- `outputs/<project>-output.json`: the original BubbleTea/Arcana JSON file.
- `data/csv/package_classification_all_compact_dependencies.csv`: package
  classifications plus dependency features.
- `data/csv/package_classification_all.csv`: fallback classification CSV if the
  compact dependency file is not present.

### Python Dependencies

The explanation pipeline uses Python with `pandas`, `python-dotenv`, and
`openai`:

```powershell
pip install pandas python-dotenv openai
```

### When To Run Each Step

1. **Generate the base JSON**

   Run the existing Javapers, Arcana, and BubbleTea generation steps first. This
   produces a JSON file such as:

   ```text
   outputs/k-9-5.304-output.json
   ```

2. **Check that the JSON and CSV rows match**

   From the workspace root:

   ```powershell
   cd tools\bubbletea-v2\llm_explanation_pipeline
   python batch.py
   ```

   `python batch.py` is a dry-run by default. It uses the `k9` preset, checks
   whether the package rows in the CSV can be found in the JSON, and does not
   call the LLM or write output files.

3. **Generate the enriched JSON**

   After the dry-run reports that the package rows match, run:

   ```powershell
   python batch.py --project k9 --run
   ```

   This calls the configured LLM, writes the enriched JSON, and writes an audit
   CSV with the generated explanations. For K-9, the default enriched output is:

   ```text
   outputs/k-9-5.304-output-classified-explained.json
   ```

4. **Open the enriched JSON in BubbleTea**

   Start the BubbleTea server:

   ```powershell
   cd ..
   python -m http.server 2825
   ```

   Then open [localhost:2825](http://localhost:2825) and upload the generated
   `*-classified-explained.json` file.

### Project Presets

`batch.py` supports these presets:

```powershell
python batch.py --project k9 --run
python batch.py --project jpacman --run
python batch.py --project monolith --run
python batch.py --project petclinic --run
python batch.py --project demoapp --run
python batch.py --project simpleapp --run
```

The default preset is `k9`.

### Custom Inputs

Use explicit paths when the JSON or CSV does not match a preset:

```powershell
python batch.py --project k9 --json ..\..\..\outputs\k-9-5.304-output.json --csv ..\..\..\data\csv\package_classification_all_compact_dependencies.csv --run
```

If the CSV contains predicted labels instead of manual labels, pass the
classification column explicitly:

```powershell
python batch.py --project k9 --csv ..\..\..\data\csv\package_features_from_json_ml_predictions.csv --classification-column predicted_classification --run
```

### LLM Model Configuration

The LLM provider and default model are configured in:

```text
llm_explanation_pipeline/llm_client.py
```
Use `OPENAI_API_KEY` for the OpenAI provider or `GOOGLE_API_KEY` for the Google
provider. The provider and model can be overridden from the command line:

```powershell
python batch.py --project k9 --provider google --model gemini-2.5-flash --run
```

### Output Used By The UI

The enriched JSON adds package metadata consumed by the BubbleTea interface:

- `classification`
- `architecture_risk_score`
- `architecture_risk_level`
- `architecture_risk_reason`
- `maintainability_impact`
- `evolution_concern`
- `recommended_review_action`
- `classification_summary`
- `detected_smells`
- `improvement_suggestion`
- `class_review_hints`
- dependency metrics and class dependency examples

The UI uses these fields for the right-side explanation panel, high-risk package
badges, class review hints, the left analytics panel, and the bottom review
diagrams.

## Deploying Your Own Instance

To host BubbleTea 2.0 locally or on your own server, follow these steps:

### Option 1: Basic Hosting
1. Clone this repository.  
2. Serve the files using a web server such as:  
   - **Python**:  
     ```bash
     python -m http.server 2825
     ```  
   - **nginx** or other web servers.

### Option 2: Docker Deployment
1. Build the Docker image:  
   ```bash
   docker buildx build -t bubbletea-v2 .
   ```  
2. Run the container:  
   ```bash
   docker run -d -p 2825:80 bubbletea-v2
   ```  
3. Access the application at [localhost:2825](http://localhost:2825).
